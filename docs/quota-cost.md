# 免费额度、限流与成本估算

核对日期：2026-10-24。产品价格、免费额度及请求限制以 `src/config/pricing.ts` 为准；本文的美元数字是第三方处理成本的估算假设，不是网站售价。

## 额度与请求次数

- 同一 `visitorId` 只在 `CreditLedger` 中获得一次免费额度；成功使用后不会按天、刷新页面或重新打开窗口补发。任务扣减和失败返还都记录在账本中。
- `/api/jobs` 每个访客每小时最多接受 3 次尝试，每个 IP 每小时最多接受 10 次尝试；两项同时生效。业务校验失败或额度不足的请求也占用请求次数；超限请求返回 429 和 `Retry-After`。
- 保留同一个访客身份时，请求次数上界是 `3 × 24 = 72 次/24 小时`；免费额度仍只有一份。失败返还额度可以允许重试，但不能绕过次数限制。
- 清除 cookie 可以产生新访客身份，不能清除服务端的同一 IP 计数。同一 IP 不断更换访客身份时，任意连续 24 小时最多通过 `10 × 24 = 240 次` 提交尝试；实际进入收费处理的任务数只会更少。
- 对于 `N` 个不同的可用 IP，上述请求上界是 `240 × N 次/24 小时`。当前规则没有全站每日总量预算，不能把 240 次表述为全站上限。攻击者更换 IP 仍能提高总请求量。

这些次数上界以服务端限流记录未被清理、多个实例共享同一限流存储，以及正确识别受信代理提供的 IP 为前提。未识别的来源合并计数，不接受客户端任意伪造的转发头作为真实 IP。

## 单次处理成本

[fal 官方 Topaz Precision 模型页](https://fal.ai/models/topaz/upscale/video/precision) 给出的 30 fps 示例为：输出 10 秒 720p 视频约 **$0.10**。页面说明这是四舍五入后的示例，最终费用取决于输出分辨率、时长和帧率，较长视频按任务汇总后取整，不能简单按示例价线性推算实际账单。

假设免费工作流只进行一次、计费输出为不超过 10 秒的 720p/30 fps Precision 增强，并以官方示例的 **$0.10/次** 作为预算单价，则：

```text
单 IP 每日增强处理预算示例
= 单次增强成本 × 每日最大可接受提交次数
= $0.10 × 240
= $24 / IP / 24 小时

N 个 IP 的相同示例 = $24 × N / 24 小时
```

这不是当前配置可保证的总账单上限。免费使用的 `FAL_FREE_VIDEO_MODEL` 水印工作流尚未配置，实际单价也尚未实测；仅在结果交付时检查 720p，不足以保证模型处理阶段也按 720p 收费。如果先做 4x 超分再缩小，增强阶段可能产生更高的计费分辨率。当前校验也没有帧率成本上限。官方 [API 输入说明](https://fal.ai/models/topaz/upscale/video/precision/api) 提供 `target_fps`，但设定该参数还可能触发插帧，需在最终工作流里确认计费和实现。

完整单次成本应写成：

```text
C_job = 增强计费 + 水印/转码计费 + 元数据探测计费 + R2 存储/请求成本
每 IP 每日任务成本估算 = C_job × 240
```

元数据接口、上传接口也可能在未提交任务时产生费用，因此整站成本还应计入独立请求及文件保留时间；上述 $24 示例只覆盖假设的增强步骤，不覆盖这些附加项。

要得到可执行的全站硬预算，需要在真实免费工作流确认单次计费上限后，再设置共享的全站每日处理配额或供应商账户消费上限。目前没有把未实现的总预算当作已存在的保护。
